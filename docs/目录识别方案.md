### 1.2 已确认的问题

| 编号 | 问题 | 影响 | 状态 |
| --- | --- | --- | --- |
| 1 | 只有固定正则一档，不可配置 | 非常用标题格式全部漏识别 | 待办 |
| 2 | 行长超过 40 字直接丢弃 | 长标题丢失 | 已修复：约束移入正则 `.{0,30}` |
| 3 | 页码按 `charCount / 3000` 估算 | 与真实分页口径不一致 | 已修复：目录改存段落行号，由阅读器换算 |
| 4 | 只读文件前 4MB，且截断处解码失败会误判 GBK | 超过 4MB 的书章节识别结果为 0 | 已修复：全量读取 + 解码回退到字符边界 |
| 5 | PDF 无 outline 时返回空数组，无回退 | 扫描件、无书签 PDF 无目录 | 待办 |
| 6 | 无手动校正入口 | 识别错误无法修正 | 待办 |

**问题 4 的实测数据**

4.5MB 的 UTF-8 中文 TXT，旧逻辑因 4MB 截断点落在多字节字符中间而回退 GBK，全文变乱码：

| 解码逻辑 | 识别章节数 |
| --- | --- |
| 旧（截断后直接判定编码） | 0 |
| 新（先回退到字符边界） | 8293 |

全量读取的性能实测（导出章节 296263 条的极端样本）：

| 文件大小 | 解析耗时 | 堆增量 |
| --- | --- | --- |
| 143.7MB | 540ms | 29MB |

该函数仅在导入书籍时执行一次，全量读取无需分块。

**关于问题 3 的实测结论**

构造 200 万字符、平均行长 32 字的中文文本对比两套算法：

| 项 | 值 |
| --- | --- |
| 真实分页数 | 663 页 |
| 实际平均每页字符 | 3016.6 |
| 目录估算页与真实页偏差 | 前 26 章均为 0 或 −1 页 |

根因：阅读器真实分页（`src/components/Reader.tsx:807-817`）按行累积到 ≥3000 断页，实际每页为 3000 加最后一行长度；目录页码按字符直接除。平均每页多出 16.6 字符，即 **0.55% 偏差**。600 页的书到末尾差 3~4 页。

**结论：偏差存在但量级小，属于「点击目录落偏一两页」，不单独开改动，随目录解析一并修复。**

修法（二选一）：

- 统一分页口径：`metadata.ts` 复用阅读器的分行逻辑计算页号
- 或目录改存**字符偏移量**，跳转时再换算为页号

**已采用方案**：目录存段落行号，阅读器分页时记录每页起始行号，跳转时二分查找换算页码（`src/utils/text.ts` 的 `lineToPageIndex`）。行号缺失的旧缓存目录回退到 `page`，保证已导入的书不失效。

## 2. TXT 目录识别：Legado 方案

Legado 是开源安卓阅读器，中文小说场景做得最完整。其 TXT 目录规则集与引擎可直接移植。

### 2.1 规则文件结构

来源：[`app/src/main/assets/defaultData/txtTocRule.json`](https://raw.githubusercontent.com/HapeLee/legado-with-MD3/main/app/src/main/assets/defaultData/txtTocRule.json)

```json
{
  "id": -1,
  "enable": true,
  "name": "目录(去空白)",
  "chapterRule": "章节识别正则",
  "volumeRule": "分卷识别正则",
  "example": "示例文本",
  "serialNumber": 0
}
```

字段语义：

| 字段 | 语义 |
| --- | --- |
| `chapterRule` | 章节标题识别正则，`MULTILINE` 模式编译 |
| `volumeRule` | 分卷识别正则，用于生成目录层级；可为空 |
| `enable` | 是否参与自动识别；关闭的规则仍可被用户手动为单本书启用 |
| `serialNumber` | 排序序号，同时决定平局时的优先级 |
| `example` | 规则说明用的示例文本 |

### 2.2 规则引擎

来源：[`app/src/main/java/io/legado/app/model/localBook/TextFile.kt:479-503`](https://raw.githubusercontent.com/HapeLee/legado-with-MD3/main/app/src/main/java/io/legado/app/model/localBook/TextFile.kt)

```kotlin
/**
 * 获取合适的目录规则
 */
private fun getTocRule(content: String): TxtTocRule? {
    val rules = getTocRules().reversed()
    var maxNum = 1
    var bestRule: TxtTocRule? = null
    for (tocRule in rules) {
        val pattern = try {
            Regex(tocRule.chapterRule, RegexOption.MULTILINE)
        } catch (e: PatternSyntaxException) {
            AppLog.put("TXT目录规则正则语法错误:${tocRule.name}\n$e", e)
            continue
        }
        var start = 0
        var num = 0
        for (m in pattern.findAll(content)) {
            if (start == 0 || m.range.first - start > 1000) {
                num++
                start = m.range.last + 1
            }
        }
        if (num >= maxNum) {
            maxNum = num
            bestRule = tocRule
        }
    }
    return bestRule
}
```

**三个关键设计**

1. **择优，而非早停**：所有启用规则全部跑一遍，统计各自的有效命中数，命中最多者胜出。与 Calibre 的「第一个通过即停」相反。中文标题格式差异大，择优比早停稳。

2. **命中间距守卫**：两次命中之间必须间隔 **超过 1000 字符**才计为新章节：

   ```kotlin
   if (start == 0 || m.range.first - start > 1000) { num++; start = m.range.last + 1 }
   ```

   作用是过滤书籍前置「目录页」——目录页里几十个章节名连续排列，间距远小于 1000，不计数；正文中的真实章节间距远大于 1000。**这一条对抑制误报的作用大于任何单条正则。**

3. **平局优先级**：`reversed()` 配合 `>=`，使 `serialNumber` 靠前的规则在命中数相同时胜出。

**配套机制**

| 机制 | 说明 | 源码位置 |
| --- | --- | --- |
| 分卷正则回查 | 由 `chapterRule` 字符串反查规则，取其 `volumeRule` 用于分卷 | `TextFile.kt:508-522` |
| 单章超长自动拆分 | 单章超 3 万字自动分为多章，可开关 | `TextFile.kt:208` |
| 目录层级 | 分卷时 `tocLevel` 置 0，其下章节置 1 | `TextFile.kt:110-113` |
| 前导空白归一 | 章节标题前导换行与空白替换为全角缩进 | `TextFile.kt:29,153-154` |

### 2.4 中文正则的否定前瞻清单

规则集里最值得复用的资产是这批否定前瞻，用于排除形近词误判：

| 片段 | 排除的对象 |
| --- | --- |
| `正文(?!完\|结)` | 「正文完」「正文结束」 |
| `节(?!课)` | 「第二节课」 |
| `集(?![合和])` | 「集合」「合集」 |
| `部(?![分赛游])` | 「部分」「部赛」「部游」 |
| `篇(?!张)` | 「篇章」 |
| `回(?![合来事去])` | 「回合」「回来」「回事」「回去」 |
| `场(?![和合比电是])` | 「场合」「场和」「场比」「场电」「场是」 |
| `部(?![分是门落])` | 「部分」「部是」「部门」「部落」 |

其他细节：

- `　`（全角空格）与 `\t` 一并列入字符类，中文排版常见
- `\s{0,4}` 允许「第 一 章」这类数字与量词间被空格撑开
- `{1,8}` 限制数字长度，防止「第 123456789 章」这类噪声
- `.{0,30}` / `.{1,30}` 限制标题长度，天然过滤长正文

## 3. Calibre 的护栏机制

Calibre 的章节规则对中文完全不可用（8 组模式均为拉丁语系关键词，唯一的非英语词是德语 `Kapitel`；默认 XPath 也只含 `chapter|book|section|part|prologue|epilogue`），但其**判定护栏**设计成熟，可直接借用。

### 3.1 护栏清单

| 护栏 | 做法 | 源码位置 |
| --- | --- | --- |
| 命中数落在区间内 | `min_chapters <= hits < max_chapters` | `utils.py:435` |
| 章节数下限按篇幅计算 | `min_chapters = ceil(词数 / 7000)`；超 20 万词改用 15000 | `utils.py:216-221` |
| 上限硬截断 | `max_chapters = 150`，防止页码、OCR 噪声被当作目录 | `utils.py:216` |
| 短文档特批 | `min_chapters < 3` 时允许命中数偏少也通过 | `utils.py:435` |
| 带标题比例自适应 | 命中行中超过 50% 带标题时，收紧为「必须有标题」 | `utils.py:410` |
| 开头去噪 | 文档开头的前 2 个命中不算章节边界 | `structure.py:168` |
| 相邻标题去重 | 连续两个标题，第二个不作为分隔点 | `structure.py:81-82` |
| 太短直接放弃 | 全文少于 50 词不执行启发式 | `utils.py:917` |

### 3.2 纯文本可直接使用的分隔线正则

来源：`src/calibre/ebooks/txt/processor.py:201`

```python
# 整行只由 空格/制表符/-/=/~///_ 组成 → 判定为场景分隔线，单独成段
txt = re.sub(r'(?miu)^[ \t-=~\/_]+$', lambda mo: sep_break(mo.group()), txt)
```

误报极低，中文小说中的 `————`、`====` 分隔线可直接命中。

### 3.3 其他可复用的弱特征

| 特征 | 判据 | 说明 |
| --- | --- | --- |
| 编号行 | `^[^'"]?(\d+(\.\|:))\s*([\w\-'"#,]+\s*){0,7}$` | 数字加点或冒号开头 |
| 无标点整行 | 整行无标点且短 | Calibre 的最终兜底，用于补齐章节数 |
| 加粗行 | 整行被成对定界符包裹（`*…*`、`_…_`、`**…**`、`~…~`） | 对应 `emphasized` 模式 |
| 字距拉开 | `([A-Z]\s+){3,}` | 对应 `C H A P T E R` 写法 |
| 空行比例 | 空行数 / 总行数 > 0.40 判定为「段落间夹空行」 | 用于先判段落结构 |

**重要前提**：Calibre 的流程是「先判段落类型，再判章节」。段落切分错误会导致章节判定失败。它的段落判定基于空行比例与缩进比例（阈值 0.15–0.75）；中文小说常无空行、靠首行缩进两格，该前提不成立，需改用 `^\s{2,}` 作为段落判据。

## 4. PDF 无书签时的目录抽取

### 4.1 pdf.js 可提供的数据

来源：`src/core/evaluator.js:2692-2698`（`getTextContent()` 返回的 item 结构）

```js
{
  str,           // 文本内容
  dir,           // 书写方向
  width,         // 宽度
  height,        // 高度
  transform,     // 6 元变换矩阵，transform[3] 为垂直缩放 ≈ 字号
  fontName,      // 字体名，可用于识别 Bold
  hasEOL,        // 是否为行尾
}
```

**结论：字号聚类法可用纯 JS 实现**，`pdfjs-dist` 已能提供字号（`transform[3]`）、加粗（`fontName`）、行边界（`hasEOL`）三项信息，无需引入新依赖。

### 4.2 可用方法

| 方法 | 原理 | 数据来源 | 适用 |
| --- | --- | --- | --- |
| 文本层关键词匹配 | 扫每页找「目录 / CONTENTS / 目次」页，解析「标题……页码」行 | `getTextContent()` | 有目录页的正式出版物 |
| 字号聚类 | 统计字号分布定出正文基准，显著大于基准的连续行判为标题 | `transform[3]` | 有文本层的绝大多数 PDF |
| 字体特征 | `fontName` 含 Bold 的行 | `fontName` | 加粗标题 |
| 版式位置 | 居中、行宽显著短、上方留白大 | `transform` 平移分量 + `width` | 组合使用 |
| 多级标题 | 字号分档映射 H1/H2/H3 | 字号分布聚类 | 层级目录 |

### 4.3 Python 生态方案（仅作算法参考，不引入）

| 项目 | 技术栈 | 离线可用性 | 许可 |
| --- | --- | --- | --- |
| [MinerU](https://github.com/opendatalab/MinerU) | Python | README 明确标注「Private · Fully Offline」，`pipeline` 后端 CPU 可跑 | 需先下载 PP-OCRv6 等模型 |
| [Docling](https://github.com/docling-project/docling) | Python | 支持 VLM 管线（GraniteDocling-258M） | MIT（模型另有许可） |
| [marker](https://github.com/datalab-to/marker) | Python + PyTorch | GPU / CPU / MPS 均可 | 代码 Apache-2.0，模型权重 OpenRAIL-M，商用有限制 |

**不建议引入**：三者均为 Python 栈且依赖模型权重（数百 MB 起），与「绿色单文件 exe」的打包目标冲突。建议只借鉴其算法思路。

## 6. 落地改造建议

### 6.1 TXT 目录解析（P1）

对应 `docs/功能总清单.md` 中「TXT 目录智能解析：默认 / 关键字 / 正则 三种方式」。

| 序号 | 改造项 | 做法 | 成本 |
| --- | --- | --- | --- |
| 1 | 规则集内置 | 移植 Legado 的 12 条启用规则，改为 JSON 配置 | 低 |
| 2 | 择优引擎 | 实现 `getTocRule` 逻辑，含**命中间距 > 1000 字符**守卫 | 低 |
| 3 | 命中数护栏 | 补 Calibre 的区间校验（下限按篇幅、上限 150）与开头去噪 | 低 |
| 4 | 三档配置 | 「默认」（内置规则集）/「关键字」（自定义前缀词表）/「正则」（用户输入） | 中 |
| 5 | 手动校正 | 允许指定单本书使用的规则，并支持手动增删章节、持久化到 `books.toc` | 中 |
| 6 | 去除 40 字上限 | 改由正则自身的 `.{0,30}` 控制长度 | 低 | **已完成** |
| 7 | 页码口径统一 | 目录改存段落行号，跳转时换算页号 | 低 | **已完成** |

**实施进度**：第 6、7 项已完成，并额外修复了问题 4（4MB 截断导致的编码误判与章节覆盖不全）。剩余顺序：1 → 2 → 3 → 4 → 5。前三项是核心能力，后两项是可用性兜底。

### 6.2 PDF 回退（P1/P2）

在 `electron/services/metadata.ts:224` 的 `if (!outline) return []` 处补回退分支：

1. 用 `getTextContent()` 逐页取 item
2. 按 `transform[3]` 做字号直方图，取占比最高的字号为正文基准
3. 显著大于基准（如 >1.2 倍）且行宽较短、`hasEOL` 独立成行的 item 判为标题候选
4. 按字号分档映射目录层级
5. 用「命中数区间」护栏过滤误报

扫描件无文本层时此路径无效，需先 OCR（P3）。

### 6.3 验收标准

| 项 | 标准 |
| --- | --- |
| 中文 TXT 章节召回 | 测试集（含知名网文、出版小说、轻小说各若干）章节识别召回率 ≥ 95% |
| 误报 | 单本书误报章节数 ≤ 3 |
| 目录页抗污染 | 含有前置目录页的书籍不产生重复章节 |
| 跳转精度 | 点击目录落点与目标章节起始位置偏差 ≤ 1 页 |
| PDF 回退 | 无 outline 的文本层 PDF 能生成可用目录 |
